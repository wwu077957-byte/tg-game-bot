# TGVault — Telegram 个人账号管理 Bot（MVP）

本次部署按用户选择，将本程序替换至现有 `@harkNewBot` 服务，因此现有群游戏功能将停止；如需另行部署，建议创建专用 Bot。多位朋友可以使用同一个 Bot，但必须先由部署者把每位使用者的 Telegram 数字用户 ID 加入白名单；数据库操作再按用户 ID 隔离。机器人只接受私聊管理命令。

## 功能与限制

- 登录仅支持二维码：`/qr` 开始，明确同意后扫描二维码；二维码过期时可点图片下方的“刷新二维码”按钮，在当前登录流程中换取新码，无需重新确认。扫码后仍可按 Telegram 的要求输入账号 2FA 密码。手机号、短信验证码、国家/地区选择、验证码重发及旧的验证码读取入口均已移除。
- 账号列表、个人备注、分组、搜索、操作记录、回收站、登录设备和 2FA 状态查看。账号列表显示 Telegram 显示名，可点击打开个人资料，并通过按钮查看 username 和数字 ID。
- 会话、账号及功能分离仍按 Telegram 用户 ID 隔离；本次移除登录路径不会清理已存账号、手机号字段或会话。
- 可选安全提醒：只提醒收到 Telegram 官方服务账号的消息，不转发正文或验证码。
- 首次使用需完成一次简单的人机验证，并加入官方频道 [@dro8r](https://t.me/dro8r)；之后每次使用都会自动核验频道成员状态。机器人必须是频道管理员，当前 `@harkNewBot` 已有管理员权限。
- 离线自动回复（默认关闭）：每个账号单独启用；夜间时段、连续空闲、未回复队列超过阈值、手动“全部切自动”四种条件任一命中即可触发。默认夜间 23:00–09:00（UTC+8）、空闲 15 分钟、队列超过 3 条；每个联系人 30 分钟内最多回复一次、每天最多 3 次。只处理私聊，不回复群组或机器人。
- 账号级提醒可通知所有者收到新私聊、自动回复已发送和新 Telegram 登录会话；设备提醒显示账号遮罩和设备名称，不包含私信正文、验证码、IP 或地点。上下文回复按账号显式开启：只对已有私聊使用最近最多 10 条文本消息和当前新消息调用 DeepSeek；新联系人始终使用固定离线文案，不会把其消息发送给 AI，也不会在对方停止发消息后主动追发。
- 主菜单、帮助、账号管理、QR 登录、设备与 2FA 状态、操作记录、回收站及自动回复设置支持中文/英文切换，语言选择按用户持久化；自动回复界面简化为按账号开启/关闭、修改一条通用回复、查看最近记录。自定义话术加密存储，默认回复仍可恢复。人工从某账号发消息会立即清除该联系人的未回复队列、解除“手动自动”并暂停该账号自动回复一个空闲阈值周期；之后可由其他离线条件重新触发。
- 自动发出的 Telegram 消息以 `auto=1` 记入本地数据库；在“最近自动回复标记”中可按账号查看对话 ID、消息 ID、场景和时间。标记不包含消息正文。
- 2FA 密码只在内存中短暂处理；机器人会尝试删除用户发来的密码，不写入数据库或日志。
- 会话、手机号、备注、分组名称和操作记录文本均使用 Fernet 加密后存储；手机号字段仍作为已存账号资料保留，不用于登录。
- QR 扫码尚未被 Telegram 确认为账号前，Bot 无法知道目标手机号，因此这段期间的 QR 登录/2FA 冷却按用户共享，而不是按目标账号区分；这是避免更换二维码绕过等待的保守限制。

MVP 不提供账号/会话转交、代他人登录、群发消息、导入/导出会话、查看/修改 2FA 密码、撤销设备会话或“账号健康分数”。自动回复只对逐号明确开启的账号生效；为计算联系人队列和记录机器人消息标记，会保存私聊对方的 Telegram ID、消息 ID、方向、时间和场景，但不读取或保存消息正文。账号添加统一使用二维码登录；本 Bot 不接受手机号或短信验证码登录。

## 部署前提

部署者需要准备：

1. 一个 Telegram Bot token；本次替换部署继续使用现有 `@harkNewBot` token。独立部署应创建专用 Bot，不要复用游戏 Bot token。
2. `my.telegram.org` 的 Telegram API ID 和 API hash。它们不是 Bot token。
3. 部署者本人及每位获准朋友的 Telegram **数字用户 ID**。白名单不接受用户名、手机号或空值。
4. Python 3.11+ 环境、稳定运行的主机、持久化且权限受限的数据目录，以及妥善保管的 Fernet 密钥。
5. 备份、系统更新、磁盘加密和密钥管理方案。备份应与运行主机分开保护；数据库之外也要保护 `.env` 和密钥副本。

## 配置白名单

复制 `.env.example` 为 `.env`，在 `ALLOWED_TELEGRAM_USER_IDS` 中填入部署者自己的数字用户 ID，再用逗号加入每一位明确获准的朋友。例如：

```dotenv
ALLOWED_TELEGRAM_USER_IDS=123456789,987654321
```

以上数字只是格式示例。请从可信的 Telegram 用户 ID 查询方式或你已信任的管理记录中确认每个人的数字 ID；不要仅凭用户名推断。每次增加或移除朋友时，部署者编辑该变量并重启机器人。移除后该用户不能继续交互，重启后也不会恢复其后台安全提醒；已有数据库记录不会自动删除。未列入白名单的用户不会获得机器人功能；白名单本身是“哪些人能使用 Bot”的总开关，并不授予他们访问其他用户账号的权限。空白、格式错误或没有任何 ID 时，Bot 会拒绝启动（fail closed）。

## 本地安装与启动

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 中填写 Bot token、API ID、API hash、白名单，并生成会话/元数据加密密钥：

```bash
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

然后启动：

```bash
python -m tg_manager.bot
```

`DATABASE_PATH` 应指向持久化的私有磁盘路径。进程用户需要对数据库及目录有写权限；程序会尽力将目录权限设为 `0700`、数据库设为 `0600`。生产环境应使用专用低权限账户和受管进程服务，限制对环境变量、数据库、备份和日志的访问；不要把 `.env`、数据库、Telegram 会话或 API 凭据提交到 Git。

### 现有数据库升级

首次运行这个版本会把旧版数据库中的手机号、备注、分组名和审计文本迁移为密文，并重写 SQLite 页面。升级前应停止旧进程并做一份受保护的备份；旧备份在迁移前可能仍含明文元数据。升级需要原有 `SESSION_ENCRYPTION_KEY`，不能用新密钥替换。确认升级成功后，再按你的保留策略处理旧明文备份。

## 信任边界与数据保护

这是高敏感应用。Telegram 登录会话相当于账号的登录凭据。二维码登录前，Bot 会明确说明：**Bot/服务器运营者能够访问可用会话，并可借此访问该账号允许的 Telegram 功能**；用户必须从 `/qr` 流程发送 `/consent` 才能继续。不信任运营者或服务器时，不要使用此 Bot，直接用 Telegram 官方客户端登录更合适。加密是静态存储保护，**不是端到端加密**。

会话、账号/分组元数据、自动回复配置和话术使用同一个 `SESSION_ENCRYPTION_KEY` 加密。运行中的应用必须能读取密钥，因此有主机、进程或密钥访问权的人仍属于可信方。丢失或更换密钥会使已保存会话和加密元数据无法解密；应离线保护并测试密钥备份，不能把密钥和数据库放在同一个可任意读取的位置。

为实现按用户隔离、自动回复去重和限流，以下必要的结构化字段仍以明文存在：Telegram 用户 ID、内部账号/分组 ID、账号与分组之间的关联、自动回复联系人的 Telegram ID 和消息 ID、方向、场景、时间、启用/暂停状态、队列计数，以及认证失败次数和冷却时间。审计动作/详情文本、完整手机号、备注、分组名称及自动回复话术均加密；审计记录限制为每位用户最近 500 条。应用读取数据时会先按当前用户 ID 过滤，再解密该用户的数据。数据库加密不能防止恶意或已被攻陷的服务器操作员读取运行进程中的数据。

Bot 与 Telegram 之间的私聊仍受 Telegram 平台和客户端保护方式约束；Bot 私聊不是端到端加密聊天。为实现自动回复，只有已开启该功能的账号会监听私聊事件并读取发件人显示名用于 `{name}`；消息正文不会写入本地数据库。若某账号显式启用 DeepSeek 上下文回复，最多 10 条近期私聊文本和当前新消息会发送给 DeepSeek 生成单条回复；其他账号及新联系人不会将消息正文发送给 AI。自动回复文本会由已登录账号真实发给联系人。机器人会尽量删除用户发来的 2FA 密码，但删除能力取决于 Telegram；用户仍应检查并清理聊天记录。2FA 密码不要转发给他人。

## 账号所有权与隔离

每个记录都按 Telegram 用户 ID 做数据库级归属检查；没有匹配的所有者 ID 时，读取、更新、删除、恢复或获取会话都会失败。所有获准用户都能和 Bot 交互，但各自只能访问本人添加的账号。朋友必须本人在私聊中完成登录授权。机器人不支持转交会话或替他人登录。

## 命令

`/accounts`、`/qr`、`/consent`、`/groups`、`/group_create 分组名`、`/move 账号ID 分组名`、`/rename 账号ID 新备注`、`/devices`、`/2fa`、`/search 关键词`、`/notify_on`、`/notify_off`、`/autoreply`、`/auto_all`、`/auto_all_off`、`/audit`、`/trash`、`/delete 账号ID`、`/restore 账号ID`、`/language`、`/cancel`、`/help`。`/qr` 是唯一添加账号的入口；二维码过期时可点图片下方按钮刷新。旧 `/add`、`/resend`、`/code` 命令及其手机号/验证码流程已移除。首次使用先做一次人机验证，再要求加入 [@dro8r](https://t.me/dro8r)；后续每次操作会自动核验频道成员。`/language` 或主菜单中的“语言 / Language”可切换中文/英文。`/autoreply` 使用可点选的账号列表，按一次即可单独开启/关闭；可设置一条通用回复，或查看最近记录。`/auto_all` 和 `/auto_all_off` 仍保留为兼容旧用法的命令。`/devices` 与 `/2fa` 可打开只含本人账号的选择器；也可在命令后输入本人账号 ID。

当前代码仅为 MVP。本次部署会替换 Bot 功能，但不会自动完成主机隔离、备份方案、数据恢复演练或真实 Telegram 账号验证。
